# 마이티 RL 학습 — DGX Spark 실행 가이드 (v2)

> v2 변경: 게임 v0.8 룰 동기화 — 딜미스 선택제(점수합 J·Q·K·A=1, 10=0.5, 조커=−1,
> 임계 0.5 이하 시 선언 '가능', 비딩 중 + 공약 확정 후 창구). 행동 207→209
> (딜미스 선언/진행), 관측 603→606 (창구 페이즈 + 딜미스 점수합·자격 특징).
> 정책이 '쓰레기 패로 딜미스 걸지, 버티고 수비할지'까지 학습 대상이 된다.

4단계 트랙 B(신경망 self-play)를 DGX Spark(GB10, ARM64, 128GB 통합 메모리)에서
실행하기 위한 패키지. 목표는 휴리스틱 v2가 못 하는 **추론**(숨은 프렌드 확률,
상대 손패 분포, 으뜸무늬 정리 계획)을 학습으로 획득하는 것.

## 구성 파일

| 파일 | 역할 |
|---|---|
| `mighty_engine.py` | JS 엔진의 Python 포트. **JS와 400게임 완전 파리티 검증 완료** (mulberry32 비트 일치 → 동일 시드 = 동일 딜) |
| `mighty_encode.py` | 관측(606차원)/행동(209) 인코딩 + `MightyEnv` 래퍼. 자가검증: `python mighty_encode.py` |
| `train_ppo.py` | 파라미터 공유 self-play PPO. `--smoke`로 동작 검증 완료 |
| `parity_test.py` | JS 트레이스 재생 대조 (`node dump-traces.js`로 트레이스 생성) |

## 인코딩 설계 요점 (으뜸무늬 추정을 위한 특징)

- **보이드 행렬** (좌석×무늬 16): 팔로우 실패 관측으로부터의 공개 추론 — "누가 어느
  무늬가 없는가"를 명시 특징으로 제공, 기루다 분포 추정의 출발점
- **무늬별 미출현 카운트** (내 손 제외 8): 기루다 정리 진행도
- **주요 카드 생존 플래그**: 마이티/조커 미출현 여부
- **지식 기반 팀 점수** (여당확정/야당확정/미확정 3): 숨은 프렌드 점수를 유출하지
  않는 행위자 시점 특징 — 학습이 프렌드 추론을 스스로 채우도록 유도
- **자기중심 좌석**(rel seat): 좌석 대칭성 제거로 표본 효율 ↑
- 바닥패 지식은 주공에게만 인코딩 (정보 비대칭 보존)

## Spark 환경 설정

```bash
# 권장: NGC PyTorch 컨테이너 (ARM64 + CUDA 정합성 보장)
docker run --gpus all -it --rm -v $PWD:/ws -w /ws \
  nvcr.io/nvidia/pytorch:25.06-py3

# 또는 네이티브: aarch64 CUDA 휠
pip install torch --index-url https://download.pytorch.org/whl/cu128
pip install numpy
```

## 실행

```bash
python mighty_encode.py          # 환경 자가검증
python train_ppo.py --smoke      # 파이프라인 검증 (CPU 가능)

# 본 학습 (Spark)
python train_ppo.py --envs 128 --steps 32768 --updates 5000 \
  --hidden 1024 --depth 4 --lr 2e-4
```

## 처리량과 병목

- 환경(파이썬 엔진)은 CPU 바운드: 단일 코어 **~9,600 결정/초** (랜덤 정책 실측).
  Spark의 20 ARM 코어 기준 멀티프로세스 확장 시 10~15만 결정/초 예상.
- 네트워크는 소형(기본 12만~수백만 파라미터)이라 GPU는 여유. bf16 autocast 기본.
- 1 게임 ≈ 60 결정 → update당 32k 스텝 ≈ 540게임. 5,000 update ≈ 270만 게임.
- **병목이 환경이면**: `Collector`를 `multiprocessing` 워커로 분산(구조상 교체 용이)
  하거나, 핫루프(legal_plays/encode)를 numpy 벡터화. 그 다음 단계는 엔진의
  C/Cython화지만, 먼저 워커 확장으로 충분한지 확인할 것.

## 학습 설계 노트

- **보상**: 종료 시 좌석별 상금/2000 (제로섬). 감가 없음(유한 10트릭 에피소드).
- **좌석 궤적 분리**: 한 게임에서 5개 에피소드(좌석별)를 얻음 — 표본 효율 5배.
- **리그 룰 고정**: 학습은 기본 config(엑셀 리그 룰)로. 룰 변형 일반화가 필요해지면
  config 특징을 관측에 추가하고 도메인 랜덤화.
- **평가**: (1) 주공 승률·평균 여당점수 추이, (2) 과거 스냅샷과의 리그전,
  (3) 휴리스틱 v2 벤치마크 — Node 브리지(`dump-traces.js` 방식의 역방향: Python이
  행동을 뱉고 Node 휴리스틱과 혼성 테이블) 또는 휴리스틱 v2의 Python 포트(후속 작업).
- **개선 로드맵**: MLP → 트릭 히스토리 Transformer 인코더(시퀀스 추론 강화),
  보조 손실(프렌드 좌석 예측 헤드 — 지도 신호는 엔진 truth, 추론 능력 직접 학습),
  NFSP/리그 학습(자기 과거 풀 상대)으로 착취 불가능성 강화.
