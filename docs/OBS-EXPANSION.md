# 관측 확장 설계 — 기루다 판단 블록 (v17 관측)

기준일 2026-08-20 · 대상 관측 `OBS_DIM 1653` → **1680** (+27)

## 왜 하는가

기루다 리드 습관(프렌드가 선을 잡으면 가장 낮은 기루다를 39% 던진다, 교사 23%)을
두 번 증류로 옮기려다 두 번 실패했다. 두 번째는 라벨 품질(A/B 검증)과 결정화
편향(무늬 추론)을 **둘 다 고친 뒤**였는데도 홀드아웃이 22.7%에서 멈췄고 게임 안
행동은 1%p만 움직였다(14-5절).

라벨을 더 뽑는 것은 답이 아니다. 홀드아웃이 낮다는 것은 **같은 관측에서 교사의
답이 갈린다**는 뜻이고, 그건 판단에 필요한 정보가 관측에 없다는 신호다. 정석이
요구하는 조건("남은 기루다 개수를 감안해서")이 실제로 관측에 없다.

## 1. 지금 있는 것과 없는 것

| 정보 | 현재 | 한계 |
|---|---|---|
| 무늬별 바깥 잔량 | `suit_counts8` | 총량만. **누구에게** 있는지 없음 |
| 좌석×무늬 보이드 | `void4x4` (16) | 최근 3트릭만, 개수 아님 |
| 내 기루다 비율 | `trump_strength2` (2) | 비율만. **서열**이 없음 |
| 무늬별 바깥 최고 | `top_out8` (8) | 랭크만, 내 연속 탑 보유는 없음 |
| 마이티·조커 소재 | `key_cand9` (9) | 키카드 전용 |
| 여당 여유 | `slack4` (4) | 점수 여유. 점수패 **잔량 분포**는 없음 |

## 2. 새 블록 (관측 끝에 붙인다)

구세대 모델이 앞부분만 읽어 그대로 돌도록 **반드시 끝에** 붙인다. v16이 1630 →
1653으로 늘렸을 때와 같은 방식이다.

### A. `trump_seat12` (12) — 좌석별 기루다 잔량 추정

상대 좌석 4개(상대 인덱스 1~4, `void4x4`와 같은 순서)마다 세 값:

```
[하한/13, 상한/13, 기대값/13]
```

계산은 좌석 가시 정보만 쓴다.

- `unseen = 13 − (지나간 트릭·테이블·내 손·(내가 주공이면 바닥패)에서 본 기루다)`
- 좌석별 용량 `cap[p]` = 그 좌석의 남은 카드 수
- **보이드 판정에서 마이티·조커 착수를 제외한다.** 둘은 팔로우 면제라 오프수트로
  나와도 그 무늬가 없다는 근거가 못 된다(v2.16.2에서 고친 규칙과 같다).
- 바닥패는 내가 주공이 아니면 미지이므로 **가상 좌석(용량 3)** 으로 배분에 넣는다.
- `상한[p] = 보이드면 0, 아니면 min(cap[p], unseen)`
- `하한[p] = max(0, unseen − Σ(다른 좌석·바닥패의 상한))`
- `기대값[p] = 보이드면 0, 아니면 unseen × cap[p] / Σ(보이드 아닌 용량)`

### B. `trump_rank6` (6) — 내 기루다의 서열

```
0: 내 최고 기루다 랭크 / 14
1: 바깥 최고 기루다 랭크 / 14        (없으면 0)
2: 내 최고가 바깥 최고보다 강한가    (0/1)
3: 연속 탑 보유 수 / 5               (A부터 끊기지 않고 내가 쥔 장수. 마이티가
                                      기루다 무늬면 포함한다)
4: 바깥 최고보다 강한 내 기루다 수 / 5
5: 내 기루다 수 / 10
```

**3번(연속 탑 보유)이 핵심이다.** 정리를 시작해도 되는지는 장수가 아니라 "내가
위에서부터 몇 장을 연속으로 쥐고 있는가"가 정한다. 지금 정책이 최저 기루다를
39% 던지는 것은 이 개념이 관측에 없기 때문일 가능성이 높다.

### C. `pts_left9` (9) — 남은 점수패 분포

```
0~3: 무늬별 미출현 점수패 수 / 5
4:   미출현 점수패 총수 / 20
5:   기루다 무늬의 미출현 점수패 수 / 5
6:   내 손의 점수패 수 / 10
7:   내 손의 기루다 점수패 수 / 5
8:   남은 트릭 수 / 10
```

"지금 정리할까, 점수 무늬를 먼저 칠까"의 근거다. 획득 점수(`team_pts3`)와 이번
트릭 점수(`table_pts3`)는 있으나 **아직 안 나온 점수패가 어디 있는지**가 없다.

## 3. 구현 순서

1. **인코더 두 곳을 동시에 고친다.** `src/mighty-master.js`의 `_sec`에 세 블록을
   추가하고 `training/mighty_encode.py`에 같은 계산을 넣는다. 순서·정규화·경계
   처리가 **비트 단위로 같아야 한다.**
2. **파리티 확인.** 인코더 파리티 7,040건 오차 0. 이걸 건너뛰면 학습이 실제
   게임과 다른 관측을 배운다.
3. **net2net 이전.** `training/net2net_obs.py`로 v16e 가중치를 새 입력 차원에
   함수 보존 이전한다. **어텐션 열이 밀리는 함정**이 있어 구간을 나눠 옮기고,
   이전 직후 출력이 v16e와 로짓 오차 1e-5 수준으로 일치하는지 확인한다.
4. **증류.** 기존 라벨을 그대로 쓴다 — 라벨은 `seed·actions·target`만 담고 관측을
   담지 않으므로 **관측이 바뀌어도 재사용된다**(`tl2_labels_*` 1,542건 ·
   `wl2_labels_*` 1,595건). 앵커는 net2net 결과, KL 1.0 · mb 256 · lr 3e-4로
   홀드아웃 정점까지.
5. **판정.** 아래 게이트를 순서대로.

## 4. 게이트 (미리 못박는다)

| # | 항목 | 기준 |
|---|---|---|
| 1 | 인코더 파리티 | 7,040건 오차 0 — 실패 시 중단 |
| 2 | net2net 직후 | v16e와 로짓 오차 1e-5 이하 |
| 3 | 홀드아웃 교사 일치 | **30% 이상** (현재 22.7%가 정보 부족의 증거이므로, 이 값이 안 오르면 확장이 효과 없다는 뜻이다) |
| 4 | 기루다 리드 행동 | 최저 기루다 리드 **30% 이하** (현재 39%, 교사 23%) |
| 5 | 클래스 오차 | trumplead 대형 실수율이 v16e(7.8%) 대비 악화 없음 |
| 6 | 수용 기준 | `accept-v4 3000 advanced` 전 항목 |
| 7 | h2h | v16e 대비 9,000판 동등 이상 |

**3번에서 떨어지면 4번 이하를 돌리지 마라.** 홀드아웃이 안 오르면 관측 확장이
목적을 달성하지 못한 것이고, 그때는 블록 설계를 다시 봐야 한다.

## 5. 위험과 대비

- **배포 용량은 안 변한다.** 관측 차원이 늘어도 모델 파일 크기는 입력층만 커진다
  (6.5MB → 6.6MB 수준). 기존 세대는 앞부분만 읽어 그대로 동작하므로 롤백은
  `NN_POOL`을 되돌리는 한 줄이다.
- **탐색과 겹친다.** 이 클래스는 이미 배포 탐색이 39% → 23%로 교정하고 있다.
  관측 확장이 성공하면 그 국면에서 탐색을 줄여 사고 시간을 아낄 수 있고,
  실패해도 현재 품질은 유지된다. **탐색을 먼저 끄고 재지 마라.**
- **파이썬 포트 동기화를 미루지 마라.** 인코더만 고치고 학습을 돌리면 파리티가
  깨진 채 라벨이 쌓인다. 1~2번 게이트를 통과하기 전에는 증류를 시작하지 않는다.
- **룰 파라미터는 건드리지 않는다.** 이번 확장은 파생량만 추가하므로 도메인
  랜덤화가 필요 없다(`rule_ctx14`는 그대로).

## 6. 예상 비용

인코더 두 곳 + 파리티 확인 반나절, net2net과 증류 한 시간, 게이트 전체 측정
서너 시간. 라벨은 재사용하므로 재생성 비용이 없다.
