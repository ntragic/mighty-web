# 마이티 웹 게임 — 버전 히스토리

1인 플레이용 5인 마이티(Mighty) 웹 게임. 서버 없이 단일 HTML 파일로 동작하며,
스코어링은 「마이티리그 시즌6」 엑셀 수식을 그대로 이식했다.

- **현재 버전**: v2.10.4 (2026-08-12)
- **배포**: itch.io(비공개) / Claude 아티팩트 공유
- **구성**: `mighty-game.html`(게임 본체·엔진 내장) · `mighty-engine.js`(독립 엔진) ·
  `mighty-engine.test.js`(테스트) · `mighty-evolve.js`(진화 학습) ·
  `mighty-ai.js`(3티어 AI 진입점) · `mighty-master.js`(신경망 인코더/추론) ·
  `mighty_master_v6b.onnx`(신경망 모델 6.5MB, 가치 헤드 포함) · `ort/`(onnxruntime-web 로컬 번들 13MB) ·
  `mighty-rl-spark-v2.zip`(RL 학습 키트)

## 릴리스 노트

### v2.10.4 — 기루다 보존 가드 (2026-08-12)

제보: 마이티가 이미 나와 승패가 결정된 트릭에서 야당이 기루다 점수카드를 버리고
스페이드를 남겼다. 기루다를 남겼으면 마지막 트릭을 확정으로 컷해 먹는다.

- **못 이기는 트릭에서 기루다를 아낀다** — 현재 최강이 상대팀이고 **남은 패가
  3장 이하**일 때 기루다를 버리려 하면 비기루다 최저(점수 아닌 것 우선)로
  바꾼다. 기루다는 남기면 컷으로 트릭을 확정 회수하고, 그 값이 후반일수록 크다.
- **인증**: v13 60,000시드 페어드에서 발화 좌석 상금 **+131.6±71.5**(n=322).
  더 좁힌 남은 2장 한정은 +357.9±154.3(n=95)으로 효과가 크지만 교정 국면이
  3분의 1이라, 그 부분집합을 포함하는 3장 기준을 택했다.
- 체인 위치는 컷 가드 **다음**이다. 먹어야 할 트릭인지 먼저 보고, 그래도 못 먹는
  트릭에서만 아낀다. 순서를 바꾸면 먹을 수 있는 트릭에서 기루다를 빼버린다.

**클래스를 두 번 고쳤다.** 첫 정의는 축을 '점수카드 여부'로 잡아 제보 국면(둘 다
점수카드)을 클래스 밖으로 분류했다. 전 구간으로 넓힌 두 번째는 발화 354판
**+23±82 중립** — 중반에는 남긴 기루다가 더 높은 기루다에 잡히거나 쓸 기회가
안 와 이득이 상쇄된다. 후반 한정에서 비로소 효과가 드러났다.

**대체재가 점수카드가 아닐 때만 발동하는 변형은 발화 0회였다.** 모델은 비기루다
대체재가 점수카드일 때만 기루다를 버린다 — 그 조건을 걸면 문제 국면이 전부 빠진다.

### v2.10.3 — 마무리 국면 표시 유지 (2026-08-11)

제보: 마지막 트릭이 보이는 동안 야당이 획득한 점수카드 더미가 사라진다. 라운드가
끝날 때 없어지는 게 맞다.

같은 뿌리의 문제다. 엔진은 마지막 트릭이 끝나는 **즉시** `phase`를 `done`으로
바꾸는데, 좌석 렌더가 `phase==='play'`일 때만 획득 더미와 트릭·점수 표기를
그렸다. 그래서 마지막 트릭을 1.4초 보여주는 동안 정작 "누가 무엇을 먹었나"는
이미 지워진 상태였다.

렌더 조건에 `done`을 포함해 **새 라운드가 시작될 때까지** 유지한다. 마무리 국면과
정산 화면에서 획득 더미·트릭 수·점수가 그대로 보인다.

### v2.10.2 — 마지막 트릭 잔상 수정 (2026-08-11)

제보: 마지막 트릭 딜레이 뒤 수거 애니메이션이 지나가고 나면 **카드가 다시
나타났다가** 결과 화면으로 넘어간다.

원인은 엔진과 UI의 경계였다. 엔진은 마지막 트릭에서 `_finishGame()`으로 바로
빠지는데, 테이블을 비우는 `pl.table = []`이 그 return **뒤에** 있다. 그래서 판이
끝난 뒤에도 `game.play.table`에 5장이 남아 있고, UI가 연출용 스냅샷(`ghost`)을
비우고 다시 그리는 순간 그 5장을 읽어 되살렸다.

엔진은 룰 구현이라 건드리지 않았다. UI에서 마지막 트릭만 **빈 테이블로 고정해
그린 뒤 곧장 결과 화면으로** 넘긴다. 수거 애니메이션 다음에 중간 화면이 없다.

`tests/timing.test.js`에 재발 방지 검사를 넣었다 — 빈 스냅샷 고정과 결과 화면
직행이 사라지면 실패한다.

### v2.10.1 — 마무리 국면 여유 (2026-08-11)

제보: 마지막 트릭에서 공개된 패가 너무 빨리 사라져 판이 어떻게 끝났는지 못 보고
정산 화면으로 넘어간다. 세팅 자동 진행 중에도 5장이 한꺼번에 깔린 장면을 볼
시간이 없다.

- **마지막 트릭은 5장이 깔린 채 1.4초 머문다.** 속도 설정(빠름/보통/느림)이나
  세팅 자동 진행과 무관하게 고정이다 — 그 화면이 마무리 국면 그 자체라 속도
  설정으로 줄일 대상이 아니다. 수거 후 정산으로 넘어가기 전에도 0.5초 둔다.
- **세팅 자동 진행의 트릭 노출을 16ms → 520ms로 늘렸다.** 나머지 구간(봇 대기·
  수거)은 0으로 두어 빠른 진행은 그대로다. 자동 진행은 결과를 빨리 보려는
  기능이지 무슨 일이 있었는지 감추는 기능이 아니다.
- 타이밍 회귀 테스트 `tests/timing.test.js` 추가 — 상수가 0으로 되돌아가거나
  마지막 트릭 분기가 수거 뒤로 밀리는 회귀를 잡는다.

  안 보인다. 탐색이 그걸 본다.

### (미배포) 수용 기준 재보정 · 미래 예측 보조 헤드 (2026-08-10)

모델 교체가 없는 연구 사이클이라 게임 버전은 올리지 않는다. 기록만 남긴다.

- **수용 기준의 '주공 승률' 판정을 고쳤다.** 구 기준(900판·점 추정 70% 이상)은
  표본 부족(주공 판 200 안팎, SE 3.2%p)과 선택 효과(승률은 주공 비율과 반비례)로
  무너져 있었다. 3,000판 실측에서 구세대 v6b가 주공 26.3%·승률 76.8%로 1위인
  반면 현행 최고 v9는 38.1%·68.8%다. 새 기준은 **3,000판 · 95% 신뢰구간 하한
  62% 이상**이고, 분리력을 실측으로 확인했다(회귀본 v11만 탈락).
- **미래 예측 보조 헤드**(`--futaux`) 추가 — 남은 트릭·점수와 마이티·기루다 소진
  시야를 맞히게 해 트렁크가 전개 결과를 표현에 담도록 강제한다. ONNX 미출력이라
  배포 비용 0, 기본값 0이라 기존 동작 불변.
- 계수 0.5는 정책을 흔들어 기각(주공 비율 42%·h2h −218). 계수 0.1(v11b)에서
  조커콜 원시 채택률 10.1% → 0.0%, 컷 미스 −30%, h2h 동등. 다만 판당 상금이
  +450 → +350이라 채택은 보류하고 기회 정규화로 재측정한다.
- 진단 도구 셋 추가 — `pimc_probe.js`(탐색 탐침), `decl_breakdown.js`(주공 승률
  분해), `c5_cert.js` 기회 정규화.

### v2.9.2 — 컷 가드 공개 전 확장 · 3차 증류 (2026-08-10)

제보 한 건이 가드 확장 하나와 증류 레시피 하나를 냈다.

- **컷 가드가 프렌드 공개 전에도 동작한다.** 지금까지 cutGuard는 공개 후에만
  걸렸다 — 팀을 몰라 "상대팀 최강 트릭"을 판정할 수 없기 때문이다. 그런데
  **확정 야당**(비주공이면서 카드 프렌드를 자기가 안 든 좌석)은 "주공이 최강인
  트릭 = 상대 트릭"임을 좌석 가시 정보만으로 안다. 그 구간으로 넓혔다.
  인증(v9, 48,000시드 페어드): 발화 좌석 상금 **+386±134**(n=161) 유의 이득.
- 제보 상황: 트릭1에서 야당이 스페이드 보이드인데 기루다 컷 대신 클럽을 버려
  주공에게 트릭을 넘겼고, 그 바람에 리드를 못 잡아 조커콜 기회까지 날렸다.
- **"야당이 조커콜의 가치를 모른다"는 가설은 기각됐다.** 야당은 조커콜을 낼 수
  있는 상황의 **96.1%**에서 이미 쓰고, 그 수는 실제로 주공 상금을 **−900±244**
  깎는 유의 이득이다. 못 쓴 이유는 리드를 못 잡아서였고, 원인은 위의 컷 미스다.

**3차 앵커 증류 — 조커콜 클래스 (배포하지 않음)**

증류 자체는 성공했다. 다만 순가치가 음수라 모델을 교체하지 않는다.

| 런 | 조커콜 CE 가중치 | 제보 국면 1순위 | 원시 채택률 | 컷 미스(1.2만 판) |
|---|---|---|---|---|
| v9 | — | 조커콜 47.3% | 10.1% | 611 |
| v10 | 1 (균등) | 조커콜 45.6% | 1.1% | — |
| v10b | 20 | 조커콜 20.3% | 1.1% | 670 |
| v10c | 80 | **♣3 일반 77.6%** | **0.0%** | 756 |

- **균등 가중으로는 이식되지 않는다.** 이 클래스는 update당 1.6샘플로 다른 관례
  (40~57샘플)의 3% 미만이라 CE가 KL 앵커에 눌린다. `--jcall-w`로 클래스 가중치를
  넣었다(기본 1.0이라 기존 동작 불변).
- **대가가 있다.** 가중치에 비례해 컷 클래스가 후퇴한다(미스 611→756, +24%).
  KL이 총 정책 이동량을 묶고 있어 한쪽을 밀면 다른 쪽이 밀린다.
- 수용 기준은 전부 PASS이고 v9 대비 h2h는 **동등**(+8.0±29.1). 즉 일반 대국에는
  차이가 없고 특이 상황에서만 갈린다.
- **배포 보류 판단**: 조커콜은 이미 jokerCallGuard가 전 표면에서 막으므로 이식의
  실이득은 발화 시 재추론 비용뿐인데, 컷 후퇴가 그보다 크다. 클래스가 몇 개 더
  쌓여 한 번에 이식할 때 이 레시피를 재사용한다.
- 증류 교사와 배포 가드의 판정 일치를 **812/812** 확인했다
  (`training/parity_jcall.py` · `tools/research/dump_jcall_states.js`).

### v2.9.1 — 조커콜 자해 가드 (2026-08-10)

실플레이 제보 한 건에서 시작해 가드 하나를 늘렸다. 역대 승격 가드 중 효과가 가장 크다.

- **조커를 프렌드로 부른 판에서 여당이 조커콜을 못 한다**. 조커 프렌드 선언은
  "조커 보유자가 내 편"이라는 공개 선언인데, 거기서 조커콜은 아군의 2인자 카드를
  최약 취급(서열 −1)으로 강제 소모시키고 콜 카드가 그 무늬 최저라 트릭까지
  넘기는 자해다. 이제 선언만 떼고 같은 카드를 그냥 리드한다.

### v2.1.6 — 하이라이트 실이득 보장 (2026-08-06)

AI 복기의 개선안이 "말한 만큼 점수를 내는지"를 실플레이 40라운드로 검증한
결과, 카드의 기대상금(시뮬 평균)이 실제 이득을 크게 과대평가하고 있었다
(약속 평균 +949 대 라인 실제 이득 +38). 구조를 바꿨다.

- **카드의 수치가 바뀌었다** — 이제 표시되는 +N은 시뮬 평균이 아니라,
  대안 수를 두고 실제 AI들이 그대로 이어갔을 때의 **이 판 기준 실제 이득**이다.
  대안 라인을 재생하면 정확히 그 점수 차가 난다(검증: 노출 19건 전부 일치).
  시뮬 평균과 승률은 판정 근거로 작게 병기된다
- **점수를 못 내는 개선안은 보여주지 않는다** — 시뮬 평균으로는 낫지만 이
  판의 실제 결과를 이기지 못하는 대안은 하이라이트에서 제외된다. 표시 건수는
  줄지만, 보이는 것은 전부 재생으로 확인된다
- 대안 라인 복기 중 '내보내기'가 시뮬 라인을 실제 기록처럼 저장하던 버그
  수정 — 이제 항상 실제 기록을 내보낸다
- 대안 라인이 실제와 같은 점수로 끝나는 경우의 설명 문구 추가, 되돌리기 시
  분석 캐시 갱신

### v2.1.5 — 대안 라인 정합 (2026-08-06)

### v2.0.0 — AI 복기: 하이라이트와 대안 라인 (2026-08-05)

라운드가 끝나면 AI가 판을 분석해 **승패를 가른 결정적 순간을 찾아준다.** 정산
화면의 "AI 복기" 버튼으로 진입한다.

**무엇을 보여주나**

- **기대상금 곡선** — 트릭이 진행되는 동안 내 기대상금이 어디서 기울었는지
  한눈에 보인다
- **하이라이트 카드** — 결정적 실수(그 수로 승패가 뒤집힘)와 손해 수(상금
  100 이상 손실)를 골라 "실제 수 → 더 나은 수"와 상금 차이, 시뮬레이션 승률
  변화(예: 3/24 → 21/24)를 보여준다. 아주 큰 부정확만 추가로 표시한다
- **강조 재생** — 카드를 누르면 그 국면으로 이동해, 잠깐 멈췄다가 문제의 수를
  확대 연출과 기대상금 표시로 재생한다
- **대안 라인** — "이 수를 뒀으면 이렇게 흘러갔다"를 실제로 재생해 볼 수 있다.
  복기 바의 버튼으로 실제 라인과 오가며 비교한다

**어떻게 판정하나.** 마스터 신경망의 가치 평가로 의심 국면을 고르고, 같은
판을 실제 수와 대안 수로 각각 24회씩 다시 플레이해(모든 좌석 마스터) 상금
분포를 비교한다. 단일 평가가 아니라 시뮬레이션 대결로 확정하며, 판정 근거
(시뮬 횟수·승률)를 카드에 그대로 표기한다. 마스터가 오라클은 아니다 —
"마스터 기준" 평가다. 내부 검증에서 하이라이트로 뽑힌 수에 대안을 강제하면
92~100%가 실제로 결과가 좋아졌다.

**코칭 모드(기본 꺼짐).** 설정 난이도 구역에서 켜면, 내 차례에 마스터가
낼 카드를 손패에 표시한다. 연습용이라 기본은 꺼져 있다.

분석은 기기에서만 실행된다(서버 전송 없음). 모델 파일명이 바뀌어 첫 실행 시
6.5MB를 다시 내려받는다. 플레이 자체(마스터의 수)는 v1.4.0과 완전히 같다.

### v1.4.0 — 마스터 AI 어텐션 인코더 (2026-08-04)

마스터 신경망을 v6으로 교체했다. 지금까지는 트릭 이력이 "누가 어떤 무늬를 몇 장
냈나"의 요약 통계로만 들어갔는데, v6은 **매 트릭의 카드가 나온 순서 그대로**를
어텐션 인코더(소형 트랜스포머)로 읽는다. 첫 리드로 무엇을 골랐는지, 기루다를
언제 꺼냈는지 같은 순서 정보가 판단 재료로 살아난다.

**달라진 점**

- **비싼 카드를 헛되이 쓰는 일이 크게 줄었다.** 이미 결판난 트릭에 마이티·조커를
  태우는 비율 18.3%→13.6%, 기루다·점수까지 넓힌 정의로 14.5%→11.5% — 역대 최저.
  야당이 잡은 트릭에 점수카드를 흘리는 비율(12.4%)은 고급 휴리스틱(13.8%)보다
  낮아졌다
- **v1.3.0의 협력 관례는 그대로.** 공개 후 기루다 리드 점수 응답 88.6%, 공개 전
  은닉(관전자 식별률 무작위 수준) 유지
- **승률 동급.** 동일 딜 3,000판×3개 시드 대역에서 평균 소폭 우세, 통계적으로는
  기존 모델과 동급. 이번 버전의 가치는 승률이 아니라 플레이 품질이다
- 모델 4MB→6.5MB, 추론 0.56ms(브라우저 실측) — 체감 차이 없음

**방법 요약.** 관측 끝에 트릭 토큰 시퀀스(트릭당 81차원×11)를 붙이고 네트워크
내부에서 2층 트랜스포머로 인코딩한다. 관례 증류(conv=0.05)를 유지한 채 학습했다.
JS↔Python 인코더 파리티 5,435건 오차 0, ONNX 변환 argmax 200/200 일치.

### v1.3.0 — 마스터 AI 협력 관례 학습 (2026-08-04)

마스터 티어의 신경망을 새 모델(v5)로 교체했다. 승률은 그대로 두고, **사람과 함께
플레이할 때 읽히는 협력**을 학습시킨 버전이다.

**배경.** 실플레이 제보를 계기로 마스터의 협력을 정밀 측정했다. 승률 자체는 문제가
없었지만, 자체 대전으로 학습한 협력 방식이 사람이 읽는 관례와 달랐다 — 프렌드가
밝혀진 뒤에도 점수를 확실히 밀어주지 않고, 주공의 기루다 리드에 점수로 응답하는
관례를 따르지 않았다. 이번 버전은 강제 개입 실험으로 "따라 해도 승률이 깎이지
않는다"고 검증된 상황에서만 인간 관례를 따르도록 학습 신호를 추가했다.

**달라진 마스터의 성향**

- **프렌드 공개 후 확실히 민다.** 주공이 기루다 리드로 이기고 있으면 점수카드로
  응답하는 비율이 23%에서 89%로 올랐다(고급 휴리스틱 79%보다 높다). 아군이 확정으로
  이기는 트릭에 점수를 보태는 비율도 52%에서 72%로 올랐다
- **공개 전에는 여전히 숨는다.** 공개 정보만 보는 관전자 모델 기준, 프렌드 식별률이
  트릭 3부터 무작위 수준(25% 내외)으로 유지된다. 밀어주기 관례는 프렌드 공개 후에만
  적용되도록 설계해 은닉 능력을 희생하지 않았다
- **야당이 이미 잡은 트릭에 점수를 덜 흘린다.** 키카드·점수 낭비(전지적 판정, 넓은
  정의)가 17.1%에서 14.5%로 줄어 역대 최저다
- **승률은 유지.** 판당 상금 +446(기준선 +485와 시드 오차 범위), 주공 승률 78.3%
  (기준선 78.4%)

**방법 요약.** 세 가지 상황 클래스(공개 후 아군 확정승 트릭 보태기, 야당 확정승
트릭 점수 회피, 주공이 이기는 기루다 리드 응답)를 같은 딜 페어드 개입 실험으로
"승률 중립" 인증한 뒤, 그 클래스에서만 관례 행동을 모방하는 손실을 PPO에 더했다.
클래스 판정은 좌석에서 보이는 정보만 쓴다. 모델 크기는 16MB에서 4MB로 줄었다
(512×3 구조, 739차원 관측).

**참고.** 무조건 기루다 응답(지는 트릭 포함)은 인증에서 유의 손해로 탈락해 넣지
않았다 — 마스터는 주공이 지고 있는 리드에는 여전히 점수를 아낀다. 이것은 버그가
아니라 검증된 판단이다.

### v1.2.6 — 모바일 레이아웃 정리 (2026-08-02)

아이폰에서 버튼이 패를 가리고, 토스트 글자가 넘치고, 모달 여백이 부족해 글자가
붙어 보이는 문제를 정리했다. **WebKit(사파리 엔진)으로 직접 렌더링해** 점검했다 —
Chromium 모바일 에뮬레이션에서는 통과로 나오던 겹침이 사파리에서 여러 건 드러났다.

**모바일 규칙이 아예 적용되지 않고 있었다.** 좁은 화면용 규칙을 파일 앞쪽 미디어
쿼리에 넣어 뒤에 오는 기본 규칙에 덮이고 있었다. 같은 우선순위면 뒤가 이긴다.
모바일 블록을 스타일 맨 끝으로 옮겨 해결했다.

**고친 것**

- 상단 HUD가 세로로 깨져 좌석과 겹쳤다. 제목을 감추고 글자 크기를 줄였으며,
  이름이 글자 단위로 쪼개지지 않게 했다. 판수·점수를 말줄임으로 잘라 딜러와 야당
  점수가 사라지던 것도 줄바꿈 허용으로 바꾸고, 늘어난 높이만큼 좌석을 내렸다
- 하단 도구 버튼이 손패를 덮었다. 손패 높이를 기준으로 그 위에 올렸다
- 토스트에 폭 제한이 없어 화면을 가로질렀다. 폭을 제한하고 트릭 영역 아래 빈
  구간으로 옮겼다
- 복기 헤드가 공개된 손패·HUD와 겹치고, 복기 바가 두 줄로 부풀어 손패를 덮었다.
  헤드를 HUD 아래로 내리고 위쪽 좌석을 그만큼 내렸으며, 바는 버튼과 여백을 줄였다.
  복기 중에는 도구 모음과 좌석의 축소 손패 사본을 감춘다(하단 손패와 중복)
- 공약 퍽에 72×72 고정 크기가 걸려 있어 내용이 상자 밖으로 흘렀다. 내용에 맞추고
  위로 올려 트릭 카드와 분리했다
- 모달과 내보내기 창의 패딩·줄간격을 넓혔다
- 세로 720px 이하 기기는 복기 중 퍽과 내 좌석 칩을 접는다. 둘 다 복기 헤드와 하단
  손패에 같은 정보가 있어 손실이 없다

**검증.** WebKit으로 402×780, 390×664, 430×800, 375×812 네 크기에서 플레이·토스트·복기
세 화면을 점검했다. 유의미한 겹침 0건, 글자 잘림 0건, 페이지 오류 0건이며 좌우 여백
차이는 0~1px이다. 데스크톱 회귀(엔진 59건·UI 스모크·복기 재개)도 통과한다.

### v1.2.4 — 키카드 가드 정밀화 (2026-08-02)

마스터 티어가 주공이 이미 이기고 있는 첫 트릭에 마이티를 얹는 장면이 제보됐다.
프렌드가 다른 다이아를 들고 있었는데도 마이티(♦A)를 냈다. 재현해 보니 규칙이 강제한
것이 아니라 모델이 스스로 고른 수였고(♦A 80.2% 대 ♦6 19.8%), 이런 낭비를 막으라고
만든 **키카드 가드레일이 통과시킨 것**이 문제였다.

**원인 — 가드의 위협 계산이 지나치게 보수적이었다**

가드는 "아군의 승리가 확정인가"를 아직 나오지 않은 카드로 판정한다. 그 국면에서
위협을 13장으로 셌다 — 조커 1장과 미출현 기루다 12장이다. 하나라도 있으면 확정승이
아니라고 보고 손대지 않는다. 그런데 그 13장은 전부 허수였다.

- 이 룰셋은 **첫 트릭에서 조커가 약하다**(`firstTrickJokerWeak`). 가드는 이 설정을
  보지 않고 조커를 위협으로 셌다
- 기루다로 자르려면 **리드 무늬가 없어야 한다**. 남은 사람은 한 명뿐이었고 그는
  다이아를 들고 있어 자를 수 없었는데, 가드는 미출현 기루다를 전부 위협으로 셌다

**수정 — 실제로 가능한 위협만 센다**

- 아직 카드를 내지 않은 사람이 없으면 위협은 0이다
- 첫 트릭·마지막 트릭의 조커 약화 룰을 반영해 그 구간에서는 조커를 위협에서 뺀다
- 미출현 리드 무늬 카드가 남은 인원보다 많으면 따라낼 카드가 있다고 보고 기루다
  위협을 세지 않는다

**검증**

기존 수용 기준의 키카드 낭비 항목은 가드와 **같은 은닉 정보 판정을 공유**해 수정
전후 모두 0.00%로 나온다 — 가드가 못 보는 국면은 지표도 기회로 세지 않는다. 그래서
모든 손패를 보고 "남은 사람 중 누구도 아군 카드를 넘길 수 없다"를 정확히 계산하는
측정기를 새로 만들어(`tools/research/keywaste_true.js`) 비교했다.

| 구성 | 키카드 낭비 | 판당 상금 |
|---|---|---|
| 가드 없음 | 5.99% | +389 |
| 기존 가드 | 4.76% | +385 |
| **수정 가드** | **2.41%** | **+385** |

같은 1,253판 기준이다. 티어 벤치(마스터 대 고급 판당 +383 → +385, 주공 승률 76.1%
동일)와 수용 기준 네 항목에 퇴행이 없다.

**승률 문제가 아니라 가독성 문제다.** 가드를 껐을 때와 켰을 때 판당 상금이 +389와
+385로 오차 안이다. 여당 점수는 합산이라 아군 트릭을 덮어써도 점수 손실이 없어,
모델이 이 선택을 구분할 학습 신호가 거의 없다. 재학습 대신 배포 측 가드로 다루는
것이 맞다는 판단이며, 남은 2.41%도 같은 성격이다.

### v1.2.3 — 복기 후 게임 재개 (2026-08-01)

복기를 마치고 나면 게임으로 돌아갈 방법이 없었다. 특히 판이 끝난 뒤 정산 화면의
`복기`로 들어간 경우, 복기를 닫아도 정산 화면이 돌아오지 않아 `다음 판` 버튼에
접근할 수 없었다. 진행이 사실상 멈춘다.

**원인 — 정산 화면을 다시 띄울 수 없었다**

`showSettlement()`이 화면 출력과 점수 반영을 함께 하고 있었다. 총점 누적과 기록
저장이 함수 안에 섞여 있어 두 번 부르면 점수가 두 번 더해진다. 그래서 복기를 닫을 때
이 함수를 다시 부를 수 없었고, 결과적으로 돌아갈 화면이 없었다.

- 정산을 **멱등하게** 나눴다. 총점 누적·기록 저장·효과음·로그는 `settledRound`
  플래그로 라운드당 한 번만 실행하고, 화면은 몇 번이든 다시 그릴 수 있다
- 복기를 닫으면 `resumeGame()`이 상태에 맞게 되살린다. 정산 단계면 정산 화면을
  다시 띄우고, 진행 중이면 봇 턴을 새로 예약한다
- 기존 워치독은 `phase !== 'done'` 조건이라 정산 구간을 복구하지 못했다. 이제
  그 구간은 `resumeGame()`이 맡는다

**복기 바의 `닫기`를 `게임으로`로 바꿨다.** 강조 버튼으로 올려 재개 동작임을 드러낸다.
`R`·`Esc` 단축키는 그대로다.

**설정에 `새 게임`을 넣었다.** 진행이 꼬였을 때의 탈출구 겸 매치 초기화다. 확인을
거친 뒤 총점·기록·라운드를 비우고 좌석 성향을 새로 배정한다. 확인 모달(z=40)이 설정
패널(z=70)에 가리므로 패널을 먼저 닫고 묻는다 — 취소하면 설정으로 되돌아온다.

### v1.2.2 — 내보내기 · 모달 경합 수정 (2026-08-01)

플레이 중 `illegal play` 오류가 뜨고, 이후 복기도 플레이 재개도 안 되는 문제를 수정했다.
제보 상황을 재현해 원인 세 가지를 확인했다.

**원인 1 — 모달 대기 중 상태 변경 (오류의 직접 원인)**

조커 선출 무늬 선택이나 조커콜 확인 모달은 `await`로 사용자 입력을 기다린다. 그런데
그 사이에 **되돌리기(Z)** 가 실행되면 게임이 이전 시점으로 재구성되어, 방금 고른 카드가
손에 되돌아온다. 사용자가 모달에서 무늬를 고르면 이미 무효가 된 수를 그대로 제출해
엔진이 `illegal play` 예외를 던졌다.

- 카드 선택 시점의 **상태 세대**를 기억하고, 모달 종료 후 세대·페이즈·차례·손패 보유를
  모두 재확인한다. 어긋나면 조용히 취소하고 화면을 갱신한다
- 제출 직전 합법수 목록으로 **최종 재검증**
- 되돌리기·새 라운드 시작 시 열려 있는 모달을 **자동으로 닫는다**

**원인 2 — 오류 후 게임 루프 정지**

예외가 나면 토스트만 띄우고 `busy` 플래그가 남은 채 루프가 멈춰 아무 조작도 받지 않았다.
이제 어떤 예외에서도 `busy`를 해제하고 루프를 재개하며, 사용자에게는 엔진 내부 메시지 대신
`그 수는 둘 수 없습니다`로 안내한다.

**원인 3 — 진행 중인 라운드는 복기 불가**

복기 대상이 **완료된 라운드**로 한정돼 있어, 정작 문제가 생긴 그 판을 볼 수 없었다.
이제 트릭이 하나라도 진행된 라운드는 **진행 중이어도 복기**할 수 있다 (선택 목록에 `진행 중` 표시).

**원인 4 — 내보내기가 조용히 실패 (itch.io 임베드)**

50라운드 매치 종료 후 `전체 내보내기`가 아무 반응이 없다는 제보를 재현했다.
itch.io는 게임을 **sandbox iframe**에 넣는데, `allow-downloads` 권한이 없으면 앵커 방식
다운로드가 **차단되면서 예외도 던지지 않는다**. 코드는 `a.click()` 호출만으로 성공했다고
판단해 "저장됨" 토스트를 띄웠고, 실제로는 파일이 생기지 않았다.

- 다운로드 지원 여부를 **사전 판정**한다 (Blob·`download` 속성·iframe sandbox 권한 확인)
- 성공하든 실패하든 **항상 결과 창을 띄운다.** 생성된 마크다운 전문과 라운드 수·용량을 보여주고
  `전체 복사`(클립보드 API → `execCommand` 폴백)를 제공한다
- 다운로드가 막힌 환경에서는 `새 창으로 열기` 버튼이 추가로 나타난다
- 라운드 수가 많으면 생성에 시간이 걸리므로 `기록을 정리하는 중…` 안내를 먼저 띄운다
- 안내 문구가 상황을 구분한다 — 저장 성공 / 임베드 차단 / 다운로드 불가

**원인 5 — 내보내기 창이 게임 모달을 덮어씀**

라운드 중간에 내보내기를 하면 이후 게임이 멈추는 문제. 내보내기 결과 창이 게임 진행용
모달(`#modal`)을 **재사용**했기 때문에, 조커 무늬 선택처럼 사용자 입력을 기다리던 모달이
있으면 그 Promise가 영원히 대기 상태로 남아 흐름이 끊겼다.

- 내보내기 전용 오버레이(`#expmodal`, 별도 z-index)로 **완전 분리**
- 닫을 때 `render()` · `pump()`를 호출해 진행을 명시적으로 재개
- `Esc`로도 닫히며, 복기 선택창은 게임 모달이 대기 중이면 열리지 않는다
- 보조 안전망으로 **정지 감지 워치독** 추가 — 모달이 없는데 3.5초간 상태 변화가 없으면
  `busy`를 해제하고 진행을 재개한다

**검증**: 조커 선출 모달 대기 중 되돌리기 시나리오로 수정 전 오류 재현 → 수정 후 오류 없이
모달 자동 종료·게임 재개·진행 중 복기 진입 확인. 모달×되돌리기 교차 스트레스 4회 `illegal` 0건.
내보내기는 일반 환경(445 KB 저장 + 결과 창)과 **sandbox iframe 모사 환경**(다운로드 차단 감지 →
복사·새 창 안내) 양쪽에서 50라운드 분량으로 확인했고, 라운드 단위·복기 화면 내보내기도 정상.

### v1.2.1 — 복기 재생 타이밍 수정 (2026-07-31)

**복기 (Replay)**

  펼쳐지고(사람 손패보다 작지만 전부 판독 가능), 사람 손패는 기존 위치·크기 그대로라
  카드 배치 인터페이스와 충돌하지 않는다
- 컨트롤: `⏮ 처음` · `▶/⏸ 재생`(게임 속도 설정 따름) · `⏭ 다음 트릭` · `내보내기` · `닫기`

**로그 내보내기**
- 라운드 단위: 복기 화면 또는 정산 화면의 `내보내기`

### v0.17.0 — 키카드 낭비 방지 (2026-07-27)

테스트 플레이 제보("주공이 기루다 Q로 탑 카드를 냈고 조커도 이미 나와 변수가 없는데,
4번째 자리에서 마이티가 나왔다")를 조사해 **중급 티어의 판단 결함**을 확인하고 수정했다.

**원인**

`_scoreFollow`의 "내가 트릭을 이기는 수" 분기는 트릭 가치를 `획득 점수 × 단가`로 계산한다.
마이티는 **그 자체가 A(점수카드)**여서, 마이티로 트릭을 가져가면 테이블 점수 + 자기 점수까지
합산되어 트릭 가치가 부풀려진다. 오버테이크 억제(−overtakeAvoid ×2)와 카드 소모 비용을
빼도 남는 경우가 있었고, 이때 마이티가 최고 점수를 받아 선택됐다.

키카드(마이티·조커) 전용 억제항인 `friendGuardKey`는 **고급 티어에만** 적용되고 있어
중급에는 이 구멍이 열려 있었다 (기본 난이도가 중급이라 노출 빈도가 높았다).

실측 재현 — 아군이 **확정으로** 이기는 트릭에서 마이티를 들고 대안도 있는 국면:

| 티어 | 기회 | 마이티 낭비 |
|---|---|---|
| 중급 (수정 전) | 111회 | **4회 (3.6%)** |
| 고급 | 102회 | 0회 |
| 마스터 (v0.16 가드레일) | 58회 | 0회 |

**수정**

키카드 억제를 티어 구분에서 분리했다.

- 아군의 승리가 **확정**이면 → **전 티어 공통** 적용 (기본 카드 감각의 영역)
- 불확실 구간(숨은 프렌드 등)의 **확률적** 억제 → 고급 티어 전용 유지
- 주공이 프렌드의 확정승 트릭에 키카드를 버리는 경우도 함께 차단

수정 후 세 티어 모두 낭비 **0%**.

**영향**

| 대결 | 이전 | 이후 |
|---|---|---|
| 고급 vs 중급 | +33 | +13 |
| 마스터 vs 중급 | +364 | +332 |

고급의 차별점은 의도대로 **프렌드 미공개 구간의 확률적 아군 추론**으로 집중된다.
명백한 실수를 기본 난이도에서 제거하는 편이 체감 품질에 유리하다고 판단했다.

- 기존 엔진은 조커를 **무조건 강제**해 이 선택지가 없었다 → 합법수에 추가
- 휴리스틱 AI 판단 추가: 트릭에 점수가 걸렸거나 후반이면 마이티로 받아 조커를 보존
- 옵션: `조커콜 시 마이티 보호` (기본 사용)

**수정 2 — 초구에 조커로 기루다를 부르는 우회 차단**
- 「초구 기루다 선출 금지」가 켜져 있어도, 조커를 선으로 내며 기루다를 **지정**하면
  같은 트릭에 기루다를 강요할 수 있어 룰이 무력화됐다
- 초구에는 조커로 기루다를 지정할 수 없도록 차단 (2트릭부터는 정상 허용)
- 옵션: `초구 조커로 기루다 지정` — 금지(기본) / 허용

**수정 3 — 마스터 티어 키카드 가드레일**
- v3 모델이 드물게(조커 선 50회 중 1회) **아군이 확정으로 이기는 트릭에 마이티를 얹는**
  낭비를 보였다
- 아군 확정승 + 대안 존재 시 마이티·조커를 가장 값싼 카드로 대체하는 가드레일 추가
  (트릭 손실이 없는 구간에서만 발동)
- 결과: 마스터 티어 **+331 → +364**(중급 상대), **+368 → +380**(고급 상대),
  주공 승률 78.3% → 80.5%

**동기화**: 세 룰 모두 Python 엔진에 반영, JS↔Python 파리티 400/400 재확인

- 딜링(53장) → 비딩 → 바닥패 교환·공약 수정 → 프렌드 지정 → 10트릭 → 정산
- 마이티 무늬 전환, 조커콜, 초구·막트릭 조커 제약, 초구 기루다 선출 금지, 팔로우 강제
- 모든 룰이 config 객체로 조정 가능 (2단계 설정 UI가 그대로 노출)

**스코어링 (엑셀 이식)**

```
점수 = ((목표−13)×300×(승 ±1) + (승 ? (획득−목표+1)×200 : (획득−목표)×200)) × (노기루다 ? 2 : 1)
상금 = clamp(점수, ±2,000)   // 노기루다 ±3,000, 런(20점)은 캡 고정 지급
배분 = 주공 ×2 (셀프 ×4) · 프렌드 ×1 · 야당 각 −1   // 완전 제로섬
```

**검증**: 엑셀 실데이터 17개 행 완전 일치, 랜덤봇 10,000판 불변식(카드 보존·점수 총합 20·제로섬) 통과, 초당 약 9,000판 처리

## RL 학습 키트 (트랙 B, GPU 대기)

DGX Spark(GB10) 타깃. 휴리스틱이 도달하기 어려운 **추론 영역**(숨은 프렌드 확률,
상대 손패 분포, 다중 트릭 계획) 학습이 목표.

| 파일 | 역할 |
|---|---|
| `mighty_engine.py` | JS 엔진 Python 포트 — mulberry32 비트 일치로 **동일 시드 = 동일 딜** |
| `mighty_encode.py` | 관측 606차원 / 행동 209 인코딩 + Gym 스타일 환경 래퍼 |
| `train_ppo.py` | 파라미터 공유 self-play PPO (마스킹 정책, bf16, 체크포인트) |
| `parity_test.py` | JS 트레이스 재생 대조 |

**인코딩 핵심 특징** — 보이드 행렬(좌석×무늬), 무늬별 미출현 카운트, 주요 카드 생존 플래그,
지식 기반 팀 점수 3분해(여당확정/야당확정/미확정), 자기중심 좌석 인코딩

**검증 상태**: 파리티 400/400, 인코더 자가검증 300게임 제로섬, PPO 스모크 통과,
단일 코어 처리량 약 9,600 결정/초
