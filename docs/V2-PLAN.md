# v2.0 계획 — AI 복기: 하이라이트와 대안 라인 (2026-08-05 초안)

v1.4.0으로 마스터의 플레이 품질(관례·낭비)은 목표 수준에 도달했다. v2.0은 방향을
바꿔 **인간 플레이어를 성장시키는 기능**에 투자한다. 핵심은 수동 복기 이전에,
게임이 끝나면 AI가 결정적 국면을 찾아 하이라이트로 보여주는 것이다.

---

## 1. 무엇을 하이라이트하나 — 판정의 정의

체스 리뷰(블런더/미스/최선)와 같은 구조를 마이티에 맞게 정의한다. 판정 주체는
마스터(v6) 정책이고, 로컬 게임은 전 좌석 손패를 클라이언트가 알고 있으므로
분석 시점에는 완전 정보 시뮬레이션이 가능하다.

| 등급 | 정의 | 판정 방법 |
|---|---|---|
| 결정적 실수 | 그 수로 승패가 뒤집혔다 | 롤아웃에서 대안 수는 승, 실제 수는 패가 다수(≥2/3) |
| 손해 수 | 승패는 안 바뀌나 상금 손실 | 기대상금 차 ≥ 임계값(예: 판당 100) |
| 부정확 | 마스터 최선수와 다르고 EV 소폭 손실 | 스크리닝 단계에서만 표기, 기본 비노출 |
| 잘한 수 | 마스터 저확률 수인데 EV 우위 | 긍정 피드백용, 라운드당 최대 1건 |

**판정 원칙 (이번 세션에서 확립한 방법론 그대로):**
- 최종 판정은 페어드 롤아웃이다 — 같은 국면에서 실제 수와 대안 수로 각각 N회
  플레이아웃(모든 좌석 마스터 정책, 시드 고정)해 상금 분포를 비교한다. 단일
  가치평가는 스크리닝일 뿐 판정이 아니다. Phase E 개입 실험 인프라의 재사용이다.
- 마스터는 오라클이 아니다 — "마스터 기준" 평가임을 UI에 명시하고, 롤아웃
  표본수와 뒤집힘 비율을 함께 보여준다. 확신 못 하는 국면은 하이라이트에서 뺀다.
- 결과 편향 차단 — 진 판에서만 실수를 찾지 않는다. 이긴 판의 손해 수, 진 판의
  "어쩔 수 없었음"(대안이 없던 국면)도 같은 기준으로 표기한다.

## 2. 판정 파이프라인 — 2단계

**1단계 스크리닝 (게임 직후, ~1초).** 인간의 플레이 결정 각각에 대해
one-step 가치 평가: 실제 수 이후 상태의 V와, 정책 상위 대안 수 이후 상태의 V를
비교(ΔEV). 트릭별 EV 곡선도 여기서 나온다. 결정당 추론 ~10회, 총 수백 회 —
wasm 0.56ms 기준 1초 미만.

**2단계 롤아웃 확정 (백그라운드, 수 초~수십 초).** ΔEV 상위 K개(기본 5) 국면만
페어드 롤아웃 N=16~32로 확정 판정. 결정당 비용 ≈ 2수 × 32롤아웃 × ~40스텝 ×
0.56ms ≈ 1.4초. Web Worker에서 돌려 UI를 막지 않고, 완료되는 대로 하이라이트
카드가 채워진다. 모바일은 N을 낮추고 "정밀 분석" 버튼으로 승격.

**대안 라인 생성.** 결정 시점부터 대안 수를 두고 이후 전 좌석 마스터
argmax + 고정 시드로 진행한 결정론적 라인 하나를 저장한다. "이렇게 뒀으면
이렇게 흘러갔다"를 고스트 재생으로 보여주는 재료다.

## 3. UX

- 라운드 정산 후 "AI 복기" 진입 → 상단에 트릭별 EV 곡선(어디서 기울었나),
  아래에 하이라이트 카드 리스트(트릭 번호·등급·요약 한 줄·상금 차)
- 카드 클릭 → 해당 국면으로 복기 점프, 실제 라인 ↔ 대안 라인 토글(고스트 카드
  반투명 표시), 재생/스텝 컨트롤은 기존 복기 UI 재사용
- 설명은 템플릿 생성: 판정 도구의 재료(현재 최강·위협·잠금 여부·팀 인지)로
  "♠A 대신 ♦3이면 프렌드 조커가 살아 트릭 8을 가져간다" 식 1~2문장.
  guard_trace / explain_move의 로직 이식
- 매치(다라운드) 종료 시 "이번 매치 결정적 순간 3선" 요약
- 복기 export에 분석 결과 포함(공유 시 하이라이트 재현)

## 4. 필요 기반 작업 (모델 재학습 불필요)

1. **가치 헤드 ONNX 재수출** — 현재 export는 PolicyOnly(logits만). value 출력을
   추가한 v6 재수출 + 캘리브레이션 확인(V 예측 vs 실제 상금 상관, 학습 로그
   v-loss 0.29 수준이면 스크리닝용으로 충분한지 실측). 파일 크기 영향 미미.
2. **엔진 스냅샷/분기 API** — 복기용 액션 배열에서 임의 시점 재구성은 이미
   가능(결정론 엔진 + 시드). 필요한 것은 분기 실행(대안 수 주입 후 진행)의
   가벼운 래퍼와, 분석 중 UI 상태와의 격리.
3. **분석 워커** — Web Worker에 엔진+인코더+ort 세션 로드. ort wasm은 워커에서
   동작 확인 필요(스레드/COOP·COEP 이슈 — itch iframe 제약 실측 선행).
4. **인간 결정 로그** — 현재 복기 데이터에 인간 좌석 결정 시점은 있음. 분석
   대상 필터(플레이 페이즈 결정만 1차, 입찰·프렌드 지정은 P4)만 추가.

## 5. 단계 (Phase)

| 단계 | 내용 | 산출물 | 예상 |
|---|---|---|---|
| P0 | 기반: value 재수출·캘리브레이션, 워커+ort 실증, 분기 래퍼 | 기술 스파이크 통과/실패 보고 | 0.5일 |
| P1 | EV 곡선 + 스크리닝 | 정산 후 EV 그래프, 의심 국면 내부 리스트 | 1일 |
| P2 | 롤아웃 확정 + 하이라이트 카드 | 등급 판정·카드 UI·복기 점프 | 1일 |
| P3 | 대안 라인 고스트 재생 + 템플릿 설명 | 라인 토글 재생, 설명 1~2문장 | 1~2일 |
| P4 | 확장: 입찰·프렌드 지정 분석, 매치 요약, 세션 통계, 코칭 모드(실시간 힌트 토글) | 별도 결정 | — |

P0의 실측(워커에서 ort, itch iframe COOP/COEP)이 실패하면 분석을 메인 스레드
청크 실행으로 대체한다 — 기능은 유지되고 진행바만 필요해진다.

## 6. 검증 — 하이라이트 자체를 검증한다

기능의 신뢰가 곧 가치다. 릴리스 게이트에 두 지표를 추가한다.

- **하이라이트 정밀도**: 시뮬레이션 게임(마스터 vs advanced, 인간 좌석을
  advanced가 대행)에서 뽑힌 "결정적 실수"에 대안 수를 강제했을 때 실제로
  결과가 뒤집히는 비율 ≥ 80%. 기존 페어드 개입 도구 재사용.
- **재현성**: 같은 판 재분석 시 하이라이트 동일(시드 고정 확인).
- 성능 게이트: 스크리닝 ≤ 2초(데스크톱)/5초(모바일), 정밀 분석 중 UI 60fps.

## 7. 범위에서 뺀 것

- 모델 재학습 — v6 그대로. 분석 품질이 부족하면 그때 가치 헤드 전용 미세조정 검토.
- 자연어 LLM 해설 — 템플릿으로 시작. 서버 없는 정적 배포 원칙 유지.
- 온라인 대전·계정 — v2.0 범위 아님.
