# 배포 가드 관리 문서

최초 릴리즈 신경망(v0.11.0, `mighty_master.onnx`) 이후 배포 경로에 추가된
후처리 가드의 목록과 근거, 학습 통합 상태. 가드를 추가·제거·모델에 통합할 때
이 문서를 갱신한다. 모델 파일 이력은 `docs/MODELS.md`, 인증 방법론은
`docs/TRAINING-PLAN.md` 검증 원칙 참조.

**가드란**: 신경망 argmax 이후에 적용되는 규칙 기반 교정. 모든 정책 노출 표면
(실플레이 에이전트·코칭·AI 복기 시뮬)이 같은 최종 경로를 재사용한다 —
`chooseAction → actionToEngine → AI.applyGuards`. v2.9.0부터 체인은
`src/mighty-ai.js`의 **`applyGuards` 한 함수에만** 있다. 이전에는 세 표면이
각자 체인을 복사해 갖고 있어 한 곳만 구버전으로 남는 버그가 났다 —
가드를 추가·삭제·재정렬할 땐 이 함수만 고친다.

**발화율 실측** (전좌석 마스터 자가대전 600판, `tools/research/guard_fire.js`,
플레이 액션 대비):

| 모델 | key | top | tfeed | cut | dlead | c1 |
|---|---|---|---|---|---|---|
| v7 | 1.31% | 0.00% | 0.00% | 0.50% | 0.51% | 0.33% |
| v8 | 1.23% | 0.00% | 0.00% | 0.16% | 0.57% | 0.26% |
| v9 | 1.31% | 0.00% | 0.00% | 0.08% | 0.37% | 0.19% |

top·tfeed는 마스터끼리는 클래스 자체가 발생하지 않는다(내재화 또는 상황 부재).
cut은 v7→v9로 6분의 1까지 줄었지만 0이 아니라 제거하지 않는다.

**승격 관문**: 같은 딜 페어드 개입 실험에서 유의 이득(또는 무해 확정 + 명백한
가독성 이득)일 때만 배포한다. 조건부 지표·직관·단일 국면 실측만으로는 승격
금지 — 아래 "탈락 사례"가 이 관문이 실제로 막아낸 목록이다.

인증(v6b에선 중립 +73±172)으로 v2.5.0에서 모델과 함께 도입.

상세:

### keyCardGuard (`src/mighty-ai.js`)

- **필요성**: 자가대전 NN은 결판난 트릭의 카드 가치 차이에 무감(승패 동일 →
  그래디언트 없음). 사람 눈에는 마이티를 아군 조커 위에 얹는 장면이 치명적
  어색함이라 가독성 목적으로 도입.
- **판정은 좌석 가시 정보만** — 미출현 카드 위협 논리. 전지적 판정 아님.
- **롤백**: `createAgent({keyGuard:false})`.
- **모델 통합 전망**: 세대마다 자체 낭비가 줄고 있어(18.3→13.6→11.5%) 언젠가
  제거 검토 가능. 제거 조건: 가드 OFF 낭비가 ON과 통계 동급이 될 때.

### topLeadGuard (`src/mighty-ai.js`)

- **필요성**: NN의 "낮은 기루다 탐색" 습관이 위 서열 부재 상황에서 순손해
  (T=1 학습 대 argmax 배포 격차 + 자가대전 사각). 리드 무늬 선택 자체는 강제
  하지 않음 — 그 변형(any)은 실측 중립(+69±260)으로 미인증.
- **롤백**: `createAgent({topGuard:false})` 또는 태그 v2.2.0 재배포.
- **모델 통합 전망**: 앵커 증류(아래) 1순위 후보 — 이식 자체는 b3top에서
  99.5% 입증됨.

클래스를 세 갈래(초구 프렌드 / 공개 프렌드 전체 / 여당 전체)로 갈라 넓히고,
리드 카드 서열 상한(rank≤10 — J·Q·K 리드는 정당한 뽑기로 보고 제외)으로 좁힌
5종을 v9에서 스윕했다. 2,400시드에서는 다섯 종 모두 이득 방향(+287~+441)이라
승격 직전까지 갔지만, 9,000시드 독립 배치에서 −101±274로 뒤집혔다.

교훈 하나 추가: **발화 판 100개 안팎의 배치는 부호를 못 정한다.** 이 클래스는
발화율이 낮아(2,400시드에 92판) 2,400시드 배치 하나로는 ±485의 노이즈에 묻힌다.
승격 판단은 발화 판 300개 이상에서 한다.

또 하나 — 인증 하네스의 `seenSet`이 좌석과 무관하게 바닥패(`discard`)를 세고
있었다. 바닥패는 주공만 아는 정보라 배포 가드가 쓸 수 없다. 좌석 가시 정보로
고쳤다(이번 클래스에서는 결과가 같았지만 다음 클래스에서는 갈릴 수 있다).

## 운영 원칙

1. **추가**: 실플레이 제보 → 클래스 정의(좌석 가시 정보만) → 페어드 개입 인증
   → 유의 이득(또는 무해+명백 가독성)일 때만 가드 구현 → 전 표면 동일 경로
   적용 → 단위 테스트 + 릴리스.
2. **롤백**: 가드별 opts 스위치 + 게임 버전 태그 + dist/stage 보관 3중
   (`docs/MODELS.md` 절차).
3. **모델 통합(앵커 증류)**: 가드가 4~5개에 이르렀으므로 다음 학습 사이클에서 PPO 없이 conv CE + 원본
   KL 앵커만으로 짧게 미세조정해 일괄 통합한다 — b2x·b3top을 죽인 "동반 PPO
   드리프트"를 구조적으로 제거하는 방식. 통합 후 가드는 안전망으로 유지하고
   발화율 0 확인 뒤 제거.
4. **장기**: 리그 학습(NFSP류)으로 자가대전 사각(자기가 안 하는 공격에 무노출)
   자체를 줄인다 — 가드 수요의 근본 원인 제거.
