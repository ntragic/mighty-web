# ONNX 모델 레지스트리

마스터 티어 신경망의 버전별 특징과 이력. 배포 모델을 바꿀 때 이 문서를 갱신한다.

**관리 규칙**

1. 배포 모델 경로는 `src/ui.js`의 `MASTER_MODEL`이 단일 소스다.
2. **파일 내용이 바뀌면 파일명을 개명한다** (v6 → v6b 사례). itch.io는 같은 이름의
   파일을 브라우저가 캐시하므로, 같은 이름으로 내용만 바꾸면 구모델이 계속 로드된다.
3. 배포 게이트: **`tools/accept-v4.js 3000 advanced`** — 상금 +150 · 주공 승률
   **95% 신뢰구간 하한 62%** · 주공 비율 20~40%(상금 유지 시 45%까지) · 전지적
   키카드 낭비 5% 미만 · 주공 딜미스 0. 여기에 `npm run bench` 티어 서열과
   구모델 페어드 대결(`model_h2h.js` **9,000판**, 동등/우세)을 더한다.
   기준 재보정 이력과 근거는 `docs/LOOKAHEAD-PLAN.md` 4-2절 — 900판·점 추정 70%는
   표본 부족(SE 3.2%p)과 선택 효과(승률은 주공 비율과 반비례)로 무너져 있었다.
4. 내보내기는 `training/export_onnx.py` — logits+value 두 출력, JS/파이썬 argmax
   200/200 일치 검증 포함.
5. 학습 신호 승격은 **같은 딜 페어드 개입 인증**을 통과한 클래스만
   (`docs/TRAINING-PLAN.md` 검증 원칙 — 조건부 지표 단독으로는 승격 금지).

### v4 — 규칙 기반을 넘어선 첫 정본 (v1.2.x)

688차원 관측, PPO 자가대전. 고급(규칙 기반+협력 추론) 상대 판당 +365.

비딩은 휴리스틱 위임(v0.15.0 임시조치)이었다가 재학습으로 해제.

### v5 = e2c005 — 협력 관례 증류 (v1.3.0)

Phase E. 승률은 그대로 두고 사람이 읽는 협력 관례를 이식했다. 인증 3클래스
한정 CE 증류(conv=0.05): addL(아군 확정승 트릭 보태기, 트릭6+), feedP(야당
확정승 회피), sigW(주공 기루다 리드에 프렌드 점수 응답). 기루다 응답
23.4%→88.9%, 보태기 52.1%→72.2%, 은닉(관전자 식별 31.6%) 유지, 수용 상금
+446·주공 승률 78.3%로 기준선(v5000, +485·78.4%)과 사실상 동일.
conv=0.10(e2c010)은 관례 이득 동일(포화)에 승률 비용이 커서 탈락.

### v6b = b1attn — 어텐션 인코더 (v1.4.0~)

트릭 이력을 요약 통계 대신 **카드가 나온 순서 그대로**(트릭 토큰 11×81,
관측 739→1630) 소형 트랜스포머로 읽는다. 파이프라인 무변경(네트워크 내부
reshape), 앞부분 프리픽스 호환. 기력은 e2c005 동급이나 키카드 낭비 역대 최저

value 헤드 포함 export(logits+value) — v2.0 AI 복기의 승률 추정에 사용.
원명 v6이었으나 export 수정 시 캐시 무효화를 위해 v6b로 개명(규칙 2의 유래).

## 혼합 운영 (v2.8.0~)

버전 매트릭스에서 기력이 수렴한(상호 대결 동등) 3세대를 AI 좌석에 혼합 배치해
성향차로 운영한다. 매치 시작 시 좌석별 추첨·매치 내 고정, 플레이 중 비노출
(비딩 읽힘 방지 — 페르소나 비노출과 같은 원칙), 매치 종료 화면에서 사후 공개.
코칭·AI 복기 판정은 항상 최신(대표) 모델.

**v2.10.0부터 좌석 배분이 추첨이 아니라 고정 배분 후 섞기다.** 네 좌석에
선견가 둘 · 책사 하나 · 수문장 하나. 추첨이면 한 세대가 네 좌석을 모두 차지하는
판이 생겨 성향차라는 취지가 흐려진다. 정석가(v7)는 풀에서 내렸다.
