## 1. 지금 상태

itch.io에 v2.8.0(빌드 #1867447)이 올라가 있고 main과 코드가 일치한다.
마스터 티어는 단일 모델이 아니라 세 세대를 좌석에 섞어 돌린다. 매치 시작 시
좌석마다 추첨해 매치 내내 고정하고, 플레이 중에는 어느 좌석이 어느 모델인지
노출하지 않으며(비딩이 읽히면 난이도가 흐려진다) 매치 종료 화면에서만 공개한다.
코칭과 AI 복기의 판정은 언제나 대표 모델(v9)로 한다.

| 좌석 모델 | 닉네임 | 근거 |
|---|---|---|
| v9 (`mighty_master_v9.onnx`) | 책사 | 프렌드 선언 함의 추론, 공격적 비딩, 수용 상금 +529 최고 |
| v8 | 수문장 | 야당 헌납 0·아군 잠금 낭비 0.99% — 수비 정교 |
| v7 | 정석가 | 관례 1세대 내재 — 균형 |

세 모델은 상호 대결에서 기력이 수렴했다(유의차 없음). 그래서 우열이 아니라
성향차로 운영한다는 결정이었다.

배포 경로에는 후처리 가드 6종이 걸려 있고, 실플레이 에이전트·코칭·AI 복기
시뮬이 **같은 최종 경로**를 재사용한다. v2.9.0부터 그 경로는 함수 하나다 —
`src/mighty-ai.js`의 `applyGuards()`. 순서는 keyCardGuard → topLeadGuard →
tfeedGuard → cutGuard → (async) dleadGuard → c1Guard 이고, 각 가드는
`createAgent({xxxGuard:false})`로 개별 해제된다. 예외적으로 **c1Guard만 기본
OFF**라 `{c1Guard:true}`로 켠다(v9에서 근거 소멸). 가드를 추가·삭제·재정렬할
땐 `applyGuards`만 고치면 세 표면에 동시에 반영된다 — 예전에는 세 곳에 체인이
복사돼 있어서 코칭만 구버전을 쓰는 버그가 났다.

## 3. 최근 개발 이력 (v2.2.0 이후)

v2.2.0에서 코칭 모드에 추천 근거 버블을 붙였다(판단 요인·위협 카드·점수 기대
3줄). v2.3.0은 주공이 기루다 AKQ를 들고도 낮은 기루다로 탐색하는 습관을
topLeadGuard로 교정한 릴리스이고, 이때부터 롤백을 git 태그·스테이지 보관·가드
스위치의 3중으로 갖췄다. v2.4.0은 관전 복기(좌석 칩으로 AI 시점 전환)와
자가 스크리닝 도구 `tools/research/self_review.js`를 넣어 "실수를 모아서 나중에
증류한다"는 개선 루프를 만들었고, 같은 사이클에 tfeedGuard·dleadGuard가 붙었다.

v2.5.0은 앵커 증류로 만든 v7을 배포하면서 c1Guard를 함께 도입했고, v2.5.1에
cutGuard(먹어야 할 트릭을 먹는 방향 — keyCardGuard의 역방향), v2.5.2에 복기
rewind의 트릭 단위 이동이 들어갔다. v2.6.0은 2차 증류로 컷 관례까지 내재화한
v8 배포다.

v2.7.0이 이번 사이클의 분기점이다. 사용자가 "프렌드가 주공의 특수카드를 추론하지
못한다"고 지적했고, 코드 확인 결과 관측의 key_cand가 프렌드 선언 정보를 전혀
반영하지 않고 있었다. 마이티/조커 프렌드 선언은 주공이 그 카드를 안 가졌다는
뜻이고 공개 후에는 프렌드가 가졌다는 확정 정보인데, 그게 관측에 없었다. 관측
차원은 그대로 두고(1630) 선언 함의를 주입하고, 마이티·조커 보유 좌석을 맞히는
보조 헤드를 얹어 재학습한 것이 v9다(위치 추론 정확도 0.29→0.75). 제보 국면의
♦3 추천이 ♦K로 교정되는 것을 실증했다. 같은 릴리스에 주공이 자기 보유 카드를
프렌드로 부르는 히든 셀프를 확인 모달과 함께 허용했다.

v2.8.0이 현행이며 위의 혼합 운영이다.

## 4. 방법론 — 이 프로젝트의 판단 규칙

가장 중요한 규칙은 **페어드 개입 인증**이다. 어떤 수가 이상해 보인다는 관찰만으로는
가드를 만들지 않는다. 같은 딜을 전좌석 마스터(argmax 결정론)로 두 번 돌려
개입한 판과 안 한 판의 상금 차이가 유의할 때만 승격한다. 조건부 지표가 낮은
구간은 정책이 그 구간을 스스로 만들기 때문에 결함의 증거가 아니다. 이 관문이
지금까지 12건을 걸러냈고, 그중에는 실플레이 제보가 실재했지만 평균이 반대였던
경우(C4f, A1)도 있다. 승격 기록은 5건이다.

두 번째는 **앵커 증류**다. PPO를 끄고 (인증 클래스 CE) + (자기 정책 KL 앵커) +
(가치 MSE 고정)만으로 짧게 미세조정한다. 런당 20분 정도이고, 동반 PPO가 낭비를
회귀시키던 실패(b2x·b3top)를 구조적으로 없앤다. 클래스를 추가할 땐 KL을 비례
상향해야 한다(1차 kl1.0/conv1.0, 2차 kl2.0/conv0.5 — 중간의 kl1.0 유지 시도는
주공 승률 9%p 회귀로 탈락). 다른 모델을 앵커로 쓰는 교차 증류는 하지 마라.
v9a/v9b에서 v8 앵커의 KL이 v9의 신규 추론을 지워버렸다 — 앵커 증류는 관례 이식
전용이다.

세 번째는 **결함 지형이 모델 세대에 따라 이동한다**는 것이다. C1은 v6b에서
중립, v7에서 +213 유의, v9에서 다시 −92 중립으로 근거가 소멸했다. dlead는 v6b
유의 → v8 약화 → v9 −518 재확대였다. 그러므로 모델을 바꾸는 릴리스마다 가드
전체를 재인증 스윕해야 한다. 이때 가드가 이미 교정한 출력을 검사하면 동어반복이
되므로, 인증 하네스는 `RAWPOL=1`로 해당 가드를 끈 모델 단독 측정을 병행한다.
h2h의 채택률 열은 개입 좌석만 세야 한다 — 5좌석을 합산하면 희석된다.

## 5. 자주 쓰는 절차

검증은 `npm test`(엔진 59건 + 가드 단위 테스트 + UI 스모크)가 최소선이고, AI
로직을 건드렸으면 `npm run bench`로 티어 서열(마스터 > 고급 > 중급)을 확인한다.
새 모델은 `node tools/accept-v4.js 900 advanced`로 수용 기준(상금 +150, 주공
승률 70%, 전지적 키카드 낭비 5% 미만, 주공 딜미스 0, 주공 비율 20~40%)을 통과해야
하고 `tools/research/model_h2h.js`로 구모델과 동등 이상이어야 한다.

릴리스는 `src/ui.js`의 `APP_VERSION`·`APP_BUILD`를 올리고 `docs/CHANGELOG.md`에
항목을 추가한 다음 `npm run release`, 그리고 `dist/stage-vX`(불필요 모델 제거)를
butler로 push한 뒤 status로 확인하는 순서다. `web/index.html`은 빌드 산출물이니
직접 고치지 말고 항상 `src/`를 고친다. 모델 파일은 내용이 바뀌면 반드시 개명한다
(브라우저 캐시 — v6→v6b가 이 규칙의 유래).

룰을 바꾸면 파이썬 포트도 같이 바꾸고 `node tools/dump-traces.js 400` →
`cd training && python parity_test.py`로 400/400을 확인한다. 관측을 바꿨으면
인코더 파리티 7,040건 오차 0도 함께 본다.

## 6. 앞으로의 계획

v2.9.0에서 직전 세션이 남긴 항목은 전부 처리됐다. c1Guard 기본 OFF(근거 소멸),
가드 체인 단일화(`applyGuards`), 롤아웃 온도 0.5 하향(복기 오탐 15/111 → 8/110),
C4 클래스 기각 확정. cutGuard 제거는 **보류**다 — "발화 0이면 제거" 계획이었으나
실측이 0이 아니었다(v9 자가대전 0.08%). accept-v4의 딜미스 라벨은 v2.7.0에서
이미 주공/야당을 가리도록 고쳐져 있었다(핸드오프가 낡았던 항목).

가드 쪽 잔여 과제는 사실상 없다. 6종 중 top·tfeed는 마스터끼리 발화 0이고
cut은 0.08%까지 줄었다. 다음 가드는 새 제보에서 나온다 — 관전 복기로 실플레이
실수를 계속 모으고, 페어드 인증을 통과하는 클래스가 쌓이면 3차 증류를 돌린다
(kl2.0 이상). **인증 배치 기준이 바뀌었다: 발화 판 300개 이상**에서 판단한다.
C4가 2,400시드(발화 92판)에서 +287로 보였다가 9,000시드(308판)에서 −101로
뒤집힌 것이 근거다.

장기 과제는 리그 학습(NFSP류)이다. 판단형 결함 — 마이티 무늬 리드, 공개 전
점수 태우기 — 은 인증 실측상 규칙화가 불가능하다고 확정됐고(C4 기각으로 재확인),
자가대전은 자기가 하지 않는 공격에 노출되지 않는다는 구조적 사각이 있다. 버전
매트릭스에서 유일하게 유의했던 항목이 "구세대 관례에 무임승차"(+223)였다는 것이
근거다. 이걸 하면 가드 수요의 근본 원인이 줄어든다.

## 7. 함정 (반복해서 물린 것들)

`pkill -f` / `pgrep -f`를 쓰지 마라. Bash 도구의 컴파운드 명령 문자열 자체가
패턴에 매치돼 자기 셸이 죽는다(exit 144, 이 프로젝트에서만 4회). 포트 기반으로
PID를 뽑아 kill 하거나 TaskStop을 쓴다.

사람 입력을 기다리는 모달은 `await` 사이에 되돌리기나 새 라운드가 끼어들 수
있으므로 `stateGen` 세대 카운터로 무효화한다. 게임 모달(`#modal`)과 내보내기
오버레이(`#expmodal`)를 섞으면 게임이 멈춘다(v1.2.2 실적).

이 저장소는 워크트리를 함께 쓰므로 bare `git stash`를 쓰지 마라 — 다른 세션의
스택을 건드린다. 임시 WIP 커밋을 쓰는 편이 안전하다.

UI 문자열은 한국어와 영어를 둘 다 넣는다(`I18N_EN` 사전과 `TF` 템플릿).
스코어링은 마이티리그 시즌6 엑셀 수식 이식본이라 임의로 바꾸지 않는다.
